## 3. 详细模块说明

## 首页模块

### 功能目的

首页用于承载用户进入应用后的主要操作入口，帮助中老年用户快速找到问答、FAQ、材料清单、口岸信息、操作指南、字体设置和朗读语言设置等功能。

### 主要页面 / 入口

用户打开 App 后进入 Home Tab。首页由 `HomeScreen` 渲染。

### 核心交互

- 点击“提问”进入 Chat 页。
- 点击操作指南打开 Guide 覆盖页。
- 点击 FAQ 问题进入本地 FAQ 详情页。
- 点击口岸卡片进入口岸详情页。
- 点击材料清单入口进入材料清单页面。
- 点击字体按钮进入字体大小选择。
- 点击朗读语言入口选择普通话、粤语或英文等朗读偏好。

### 当前实现状态

主体已实现。首页的 FAQ、本地口岸概览、材料入口和设置入口已存在；客服、志愿者、视频讲解等人工帮助能力当前主要为 Toast 占位。

### 涉及文件

- `ElderCareApp/app/src/main/java/com/example/eldercareapp/ui/screen/ElderCareScreens.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/ui/screen/FaqData.kt`
- `ElderCareApp/app/src/main/res/values/strings.xml`
- `ElderCareApp/app/src/main/res/values-zh-rCN/strings.xml`
- `ElderCareApp/app/src/main/res/values-zh-rHK/strings.xml`
- `ElderCareApp/app/src/main/res/values-zh-rMO/strings.xml`
- `ElderCareApp/app/src/main/res/values-zh-rTW/strings.xml`
- `ElderCareApp/app/src/main/res/values-en/strings.xml`

### 备注

口岸筛选当前主要体现为本地状态和展示，是否真实过滤所有口岸信息仍需后续确认。人工帮助类入口不能视为正式功能闭环。

## 智能问答模块

### 功能目的

智能问答模块用于回答用户关于港澳通行证、签注、过关材料、办理流程等自由提问，并以适合老年用户阅读的结构化卡片展示结果。

### 主要页面 / 入口

入口包括 Chat Tab、首页“提问”、FAQ 详情页“继续追问”、Guidance 结果中的详细政策提问、问答页快捷问题等。

### 核心交互

- 用户输入文字并发送。
- 系统调用后端 `/api/v1/chat-policy`。
- 后端调用 Dify/RAG 或读取 RAG 缓存。
- Android 展示结构化回答卡片，包括结论、步骤、材料、注意事项、来源等。
- 用户可点击场景选项继续提问，或进入材料清单。

### 当前实现状态

已接入。当前问答链路已经包含 Dify/RAG、结构化 JSON 解析、展示语言本地化、TTS 信息、RAG 缓存和本地历史保存。

### 涉及文件

- `ElderCareApp/app/src/main/java/com/example/eldercareapp/viewmodel/ChatViewModel.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/model/ChatModels.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/api/AssistantApi.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/api/ApiClient.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/ui/screen/ElderCareScreens.kt`
- `backend/app/api/routes_chat.py`
- `backend/app/services/dify_service.py`
- `backend/app/services/rag_cache_service.py`
- `backend/app/services/display_localization_service.py`
- `backend/app/services/qwen_text_service.py`
- `backend/app/schemas/chat_schema.py`

### 备注

真实问答效果依赖 Dify、知识库、DashScope/Qwen 配置。政策类回答需要继续提示以官方窗口或政府网站为准。

## FAQ 静态详情模块

### 功能目的

FAQ 静态详情模块用于承载高频、稳定、简短的问题答案，减少用户等待时间和后端 RAG 调用次数。

### 主要页面 / 入口

用户从首页 FAQ 区域点击具体问题进入 `FaqDetailScreen`。

### 核心交互

- 首页展示 FAQ 分类和问题列表。
- 点击问题打开本地详情页。
- 详情页展示简短答案、分段说明、注意事项、来源提醒和更新时间。
- 用户点击“继续追问”后，才进入 Chat 页并提交 follow-up 问题。

### 当前实现状态

已实现。`FaqData.kt` 中已包含 `shortAnswer`、`answerSections`、`tips`、`sourceNote`、`updatedAt`、`followUpQuestion` 等字段。

### 涉及文件

- `ElderCareApp/app/src/main/java/com/example/eldercareapp/ui/screen/FaqData.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/ui/screen/ElderCareScreens.kt`
- `ElderCareApp/app/src/main/res/values*/strings.xml`

### 备注

部分 FAQ 目前仅有问题文本，详情内容不一定全部补齐。FAQ 本地内容的来源链接在当前仓库中未明确记录，后续建议补充。

## 语音输入模块

### 功能目的

语音输入模块降低老年用户输入门槛，让用户可以通过说话完成提问。

### 主要页面 / 入口

主要入口位于 Chat 页底部输入区的语音按钮。

### 核心交互

- 用户点击语音按钮并授权麦克风。
- Android 录制语音文件。
- 上传到后端 `/api/v1/asr/transcribe`。
- 后端调用 DashScope ASR 获取文本。
- 前端展示识别草稿。
- 用户确认后作为问题提交给智能问答。

### 当前实现状态

已接入。已实现录音、上传、识别草稿确认、重录、手动修改和语音失败提示等流程。

### 涉及文件

- `ElderCareApp/app/src/main/java/com/example/eldercareapp/voice/VoiceRecorder.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/viewmodel/ChatViewModel.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/api/AssistantApi.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/ui/screen/ElderCareScreens.kt`
- `backend/app/api/routes_asr.py`
- `backend/app/services/asr_service.py`
- `backend/app/schemas/asr_schema.py`

### 备注

真实识别能力依赖 DashScope API Key、网络和音频质量。识别错误会影响后续 RAG 回答准确性。

## 语音朗读模块

### 功能目的

语音朗读模块用于朗读 AI 回答、操作指南步骤和本地判断问题，提升老年用户可访问性。

### 主要页面 / 入口

入口包括 Chat 回答卡片、Guide 操作指南、Guidance 办理判断页面等朗读按钮。

### 核心交互

- 用户点击朗读按钮。
- Android 优先播放后端返回的 `tts.audio_url`。
- 若没有已有音频，则调用 `/api/v1/tts/synthesize`。
- 后端生成音频并通过 `/static/tts/...` 返回。

### 当前实现状态

已接入。后端支持 TTS 音频缓存，RAG 缓存命中时也会复用稳定 `tts_text`，提高音频缓存命中机会。

### 涉及文件

- `ElderCareApp/app/src/main/java/com/example/eldercareapp/ui/screen/ElderCareScreens.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/viewmodel/ChatViewModel.kt`
- `ElderCareApp/app/src/main/java/com/example/eldercareapp/api/ApiClient.kt`
- `backend/app/api/routes_tts.py`
- `backend/app/api/routes_chat.py`
- `backend/app/services/tts_service.py`
- `backend/app/schemas/tts_schema.py`

### 备注

朗读语言可独立选择，不完全等同于系统展示语言。真实云端朗读依赖 DashScope TTS Key。

## 多语言展示模块

### 功能目的

多语言展示模块用于让界面展示语言跟随系统语言，同时支持朗读语言独立选择，适配粤港澳大湾区简体、繁体和英文使用场景。

### 主要页面 / 入口

展示语言主要跟随系统 Locale；朗读语言在首页顶部或相关入口选择。

### 核心交互

- 系统 Locale 为简体中文时展示 `zh-CN`。
- 系统 Locale 为香港、澳门、台湾或繁体脚本时展示 `zh-HK`。
- 系统 Locale 为英文时展示 `en`。
- 朗读语言可选择普通话、粤语、英文或自动。

### 当前实现状态

部分实现。资源目录包含多套 `strings.xml`，后端也有 Dify 输出本地化服务。但部分 FAQ query、快捷问题提交文本、Guide、Guidance、Toast 等仍存在硬编码中文。

## 4. 当前状态总结

当前项目已具备首页入口、智能问答、RAG、ASR、TTS、多语言、本地 FAQ、口岸静态展示、养老服务静态原型、本地历史和材料清单 mock 等主要模块。项目的核心演示闭环已经形成，但仍需明确区分正式能力与演示能力：问答、语音和朗读依赖后端及外部模型配置；口岸、养老、材料清单多为本地静态或 mock；人工帮助、地图导航、真实政务数据源等功能当前不能视为完整上线能力。
